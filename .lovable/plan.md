## 目標

依參考圖的格式重建籤表：人數不是 2 的次方時，只產生「預賽」場次讓多出來的人先打，其餘選手直接進入完整的主籤表，不再出現一堆輪空空格。

以 17 人為例：
```
預賽 1 場（2 人）→ 第一輪 16 人（8 場）→ 八強 → 準決賽 → 決賽
```
20 人：預賽 4 場 → 第一輪 16 人（8 場）→ …

## 修改內容

### 1. `buildBracket()`（`src/lib/tournament-store.tsx`）

- `main = 2^floor(log2(n))`（不超過人數的最大 2 次方），`playIn = n - main`。
- 建立主籤表：`log2(main)` 輪，第一輪 `main/2` 場，全部兩人到位 → `ready`。
- 若 `playIn > 0`，另建一個「預賽」輪（round 0，共 `playIn` 場，每場 2 人），主籤表輪次整體 +1。
- 預賽場次用位元反轉順序挑選要接到主籤表的哪些位置，讓它們平均散在上下（左右）兩半；被接上的那個主籤表格位先留空，等預賽勝者填入（狀態 `waiting`）。
- 移除原本「輪空自動晉級」的邏輯：新結構沒有輪空，因此不會再有生成後立刻結束的問題。

### 2. 輪次名稱（`roundName`）

預賽輪要顯示「預賽 PRELIM」。做法：當某一輪的場次數不等於「後一輪場次數 × 2」時視為預賽輪；其餘輪次仍用現有的由後往前命名（決賽／四強／八強／第 N 輪）。同步調整 `src/lib/tournament-export.ts` 的 `roundLabel`，讓匯出的 .txt 一致。

### 3. 籤表版面（`src/components/BracketTab.tsx`）

目前的定位演算法假設每一輪都是前一輪的一半（`prev[j*2]`），預賽輪場次較少會錯位。調整：

- 先照現有方式為主籤表各輪算好縱向位置（左右鏡像切半不變）。
- 預賽輪單獨處理：每張預賽卡片對齊它所餵入的第一輪卡片（用 `nextMatchId` 找對應卡），連接線只畫該對單一連線，就像參考圖左邊那格。
- 左右鏡像分半時，預賽卡片跟著它的目標第一輪卡片落在同一半。

### 4. 排名 / 匯出

`src/lib/standings.ts` 用 `round` 由後往前找決賽與四強，多一個預賽輪不影響；只確認 3/4 名判定仍只採計已打完的場次。

## 驗證

- 17 人：預賽 1 場、第一輪 8 場皆 `ready`，樹狀圖左右平衡，預賽格對齊目標場次。
- 20、22 人：預賽 4／6 場平均分佈於兩半，第一輪 8 場。
- 16、32 人：無預賽輪，行為與現況相同。
- 5、6、11 人：預賽數正確、無空白對戰、生成後賽事不會立刻結束。
- 在瀏覽器檢視實際版面與連接線，並匯出一次 .txt 確認輪次名稱。

## 技術備註

已存在的舊賽事需重新按一次「隨機產生賽程」才會套用新結構；資料庫結構、同步與封存邏輯不變。
