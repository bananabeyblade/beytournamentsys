## 目前發現的錯誤

**1.（實際發生）新增管理者時丟出未處理的英文錯誤**

Preview 執行階段錯誤：
```
Error: A user with this email address has already been registered
  at src/lib/admin.functions.ts:76
```
`createAdminFn` 直接把後端原始英文訊息往外丟，畫面上出現紅色錯誤頁／英文提示。資料庫確認目前已存在 `chouru@beyx.local`、`chosen8558@beyx.local`（兩者是**總管理者**），因此再用相同帳號名稱新增「管理者」就會撞到同一個登入帳號。

**2. 兩個新增流程行為不一致**

`createSuperadminFn` 遇到帳號已存在時會找出既有使用者、更新密碼並補上角色；`createAdminFn` 沒有這段處理，直接失敗。

**3. `admin_roles.email` 欄位寫入格式不一致**

管理者存的是純帳號（`chouru`），總管理者存的是完整登入信箱（`chouru@beyx.local`），管理者清單顯示與比對容易混淆。

## 修正方案

### A. `src/lib/admin.functions.ts` — `createAdminFn`
- 建立帳號前先查是否已有同一登入信箱的使用者。
- 若該使用者**已經是管理者或總管理者** → 回傳明確中文訊息：「此帳號已存在（目前為總管理者／管理者），請改用其他帳號或直接重設密碼」。
- 若使用者存在但**沒有任何角色**（孤兒帳號） → 更新密碼並補上 `admin` 角色，視為成功。
- 建立失敗時把 Supabase 的英文訊息轉成中文（帳號已被使用／密碼太弱／其他），不再外洩原始訊息。
- 角色寫入時 `email` 統一存完整登入信箱，與總管理者一致。

### B. `src/components/AccountSettings.tsx`
- 新增前先比對已載入的管理者／總管理者清單，重複時直接在表單下方提示，不必發送請求。
- 錯誤訊息維持顯示在原有的 `msg` 區塊（已是紅色提示），避免觸發全頁錯誤畫面。

### C. 顯示調整
- 管理者／總管理者清單顯示時，`@beyx.local` 後綴隱藏，只顯示帳號名稱；Gmail 等真實信箱照原樣顯示。

## 驗證
- 用已存在的 `chosen8558` 新增管理者 → 出現中文提示「此帳號已存在（目前為總管理者）」，無紅色錯誤頁、無 runtime error。
- 用全新帳號新增管理者 → 成功建立並出現在清單、可登入。
- 既有總管理者新增／移除功能不受影響。

## 技術備註
不需要資料庫遷移，僅調整伺服器函式的錯誤處理與前端提示；現有帳號與角色資料不會被改動。
