# Bug 檢查與修正方案

以下都是實際讀過程式碼後確認的問題，修正只動前端同步邏輯與報名等待畫面，不改資料庫結構、RLS 或既有合併 RPC。

## 1. 切換賽事時，舊賽事的選手會被帶進新賽事（優先）

跟隨雲端的 `apply()` 只有在「新賽事還沒發佈任何資料」時才會清掉本機殘留；如果新賽事已經有發佈過的名單，就直接跟本機（舊賽事）的名單做合併。結果是舊賽事的選手混進新賽事名單，而且會被這台裝置上傳回雲端。舊賽事的刪除記錄（tombstone）也沒清掉，可能把新賽事剛核准的同 id 選手擋掉。

修正：偵測到換賽事時，一律先清空本機名單、賽程、刪除記錄與防迴圈基準，再套用新賽事的雲端快照。

## 2. 清除賽事後，同一場又會自己跑回來

`resetTournament` 會清掉畫面與本機記錄的賽事代碼，但雲端那一場仍然是「進行中（open）」。跟隨迴圈下一次抓「最新進行中的賽事」時就把同一場撈回來，賽事卡片與 QR 又出現。

修正：清除時記住「本機已放棄的賽事 id」，跟隨迴圈遇到同一場就不再自動採用；要回到那場請從設定頁的過往賽事「進入賽事」。

## 3. 新建賽事後，其他裝置可能還停在上一場的畫面

發佈端用「內容和上次上傳的一樣就不寫」來防迴圈，但新建賽事時沒有重置這個基準。剛建立的賽事本機是空名單，字串剛好和上一次上傳相同時，就完全不會發出第一次上傳；其他管理者與觀眾要等到有人新增選手才會更新。

修正：`startNewTournament` 重置防迴圈基準與時間戳，讓新賽事一定發出一次初始狀態。

## 4. 登出後換人登入，會沿用上一位的賽事資料

登出只清掉跟隨狀態，本機仍留著上一場的賽事代碼與名單／賽程快取。下一位管理者在同一台裝置登入時，會先被還原成上一場的狀態，甚至把它重新上傳。

修正：登出時一併清掉本機賽事代碼與賽況快取，並重置合併／發佈基準。

## 5. 報名被裁判拒絕後，參賽者永遠停在「等待開賽」

`/register` 送出後只靠本機記錄顯示等待畫面，被拒絕（報名資料被刪除）時畫面不會有任何變化，參賽者不知道要重新報名。

修正：等待畫面定期確認自己的報名是否仍存在（沿用現有的公開檢查，不新增資料表），已不存在且賽事尚未開始時，提示「報名未被保留，請重新報名」並回到表單。

## 技術細節

- `src/lib/tournament-store.tsx`：`apply()` 換賽事時無條件重置本機狀態；新增 `abandonedId` 讓 `resetTournament` 不再被 `fetchLatestOpenTournament` 撈回；`startNewTournament` 重置 `lastPayload` / `lastPublishedStamp` / `lastAppliedStamp`；`logout` 清除 `beyx-active-tournament`、`beyx-live-state` 與同步基準。
- `src/routes/register.tsx`：等待畫面加入報名存在性檢查與重新報名提示。
- `src/lib/registration-check.functions.ts`：沿用現有公開檢查函式（必要時僅回傳布林值，不外洩報名資料）。
- 不改資料庫結構、RLS、`publish_live_state`。
